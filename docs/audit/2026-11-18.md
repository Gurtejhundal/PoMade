# PoMade audit and verification — 18 November 2026

What this repo does: PoMade prepares and maintains GitHub repository presentation. A CLI reads local project facts, an agent skill guides the initial review, a GitHub Action refreshes generated content after pushes, and a browser Studio exports the same README styles.

Assumed load: one developer or one CI job per repository, plus a static public website. Local and remote updates are separate operations; this is not a multi-user document database.

## Must fix — corrected

1. **The two README engines disagreed and invented product facts.**
   - What this is: the old Studio had six independent template modules; the CLI had a different author.
   - Problem: templates emitted nonexistent API signatures, binary download links, passing badges, and unverified privacy claims.
   - Fix: one browser-safe Markdown renderer in `src/core/content/templates.ts`, used by the CLI and Studio. Three styles: Simple, Signature, Motion. Owner claims are distinguished from observed configuration.
   - If skipped: repositories receive attractive but false documentation.

2. **The website simulated a repository instead of rendering a README.**
   - What this is: the original redesign wrapped content in branch controls, file bars, repository tabs, and an About sidebar.
   - Problem: it missed the owner's requested visual direction.
   - Fix: a standalone white README document, large centered mascot, title rule, italic tagline, flat badges, Markdown-like sections, and real-data Star History. All five functional routes remain.
   - If skipped: the core product impression remains wrong despite working code.

3. **Malformed markers could cause a full-document replacement.**
   - What this is: the planner caught marker parsing errors and proposed a fresh document.
   - Problem: automation could turn a malformed marker into a destructive rewrite.
   - Fix: parsing errors stop the plan. Nested/crossed sections are rejected; automatic sync refuses an existing unmarked README.
   - If skipped: handwritten content can be lost.

4. **Parent symlinks could escape the write boundary.**
   - What this is: filesystem validation checked lexical paths and final symlinks, but missed a linked parent directory.
   - Problem: `linked/new/file` could resolve outside the target repository.
   - Fix: validate canonical existing ancestors before reading/writing/scanning; check actual target sizes; refuse sensitive-file writes; use exclusive random temporary filenames.
   - If skipped: output can be written outside the intended project.

5. **Saved plans were not the plans being applied.**
   - What this is: planning could save a file, while apply generated a fresh plan.
   - Problem: the applied result could differ from what was reviewed.
   - Fix: `apply --plan` parses the saved artifact, checks repository identity, proposal hashes, and current target hashes.
   - If skipped: approval refers to a different change.

6. **Community initialization could replace owner policies.**
   - What this is: repeated initialization regenerated contribution, security, and license files.
   - Problem: custom policies could be replaced; security text invented contacts and response commitments; some license files were incomplete notices.
   - Fix: initialization skips existing files. No invented response promises/contact. Full-file license creation is limited to the complete bundled MIT text; other owner-selected licenses must be supplied in full.
   - If skipped: users receive incorrect legal or security-reporting instructions.

7. **Test configuration was treated as successful verification.**
   - What this is: release planning inferred passing tests from a manifest script and maturity heuristic.
   - Problem: a failing or never-run suite could be described as verified.
   - Fix: release drafts do not claim tests passed. Badges link to actual workflow state. Documentation identifies configured commands as configuration.
   - If skipped: release claims are unreliable.

8. **The push workflow was missing.**
   - What this is: a plugin description existed without actual push-triggered maintenance.
   - Problem: code could ship without README or metadata upkeep.
   - Fix: `init`, `sync`, a reusable composite Action, and PoMade's own push workflow. Metadata uses a scoped token; ordinary generated-file commits use the workflow token.
   - If skipped: the requested product behavior does not exist.

9. **A bot commit could include unrelated staged content.**
   - What this is: a normal commit consumes the entire index.
   - Problem: a workflow calling the Action after staging another file could accidentally publish that file.
   - Fix: commit only README and the two generated covers; use a normal, non-force push.
   - If skipped: unrelated work can be included in a presentation commit.

10. **The diff algorithm could exhaust memory on large READMEs.**
    - What this is: a full quadratic comparison table was allocated for every pair of documents.
    - Problem: thousands of changed lines could consume excessive memory, and final-newline differences produced invalid patches.
    - Fix: bound the comparison table and use a full replacement diff beyond that bound. Handle missing terminal newlines. Verify patches by applying them with Git.
    - If skipped: a presentation preview can crash or emit unusable patches.

11. **Malformed manifest fields could crash authoring.**
    - What this is: arbitrary npm JSON values were cast into typed facts.
    - Problem: an object-valued name or numeric command could enter string rendering.
    - Fix: runtime validation; malformed manifests produce warnings. Root manifests take precedence over nested examples; fingerprint complete parsed facts.
    - If skipped: ordinary hostile or malformed repository input breaks scanning/authoring.

12. **Production dependencies had published advisories.**
    - What this is: the old stack contained Next.js 14 and Zod 3, plus an unused Tailwind toolchain.
    - Problem: the installed audit reported critical/high advisories.
    - Fix: Next.js 16.4.6, React 19, Zod 4.6.7, patched test tooling; remove Tailwind, PostCSS configuration, Autoprefixer, clsx, and tailwind-merge. Use existing plain CSS. Website production audit: zero findings after the change.
    - If skipped: published issues remain in the shipped stack.

## Should fix / remaining boundaries

13. **An upstream development-tool advisory has no published patch.**
    - What this is: Vitest/Vite use picomatch 4.0.7 for file-pattern matching.
    - Problem: npm reports five high-severity dependency entries for one underlying regular-expression denial-of-service advisory. The [reviewed advisory](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) lists no patched version as of this audit.
    - Fix: update when the upstream patch is released. Keep test/watch tooling local and use trusted project-controlled patterns. Do not downgrade Vitest to the older vulnerable version suggested by npm's automated resolution.
    - If skipped: attacker-controlled glob patterns supplied to the development tools can consume CPU. These packages are development dependencies, not the shipped CLI runtime or website production dependency tree.

14. **Repository inspection is heuristic, not semantic verification.**
    - What this is: non-npm manifest extraction, project-kind/maturity checks, drift mentions, and the legacy evidence ledger use structural or textual signals.
    - Problem: they cannot prove arbitrary feature prose, API behavior, release availability, or production readiness.
    - Fix: the new author emits conservative facts and reviewed owner input; the UI/docs state the boundary. A full parser/semantic-analysis replacement is outside this presentation change.
    - If skipped: treating an audit score as certification would still be misleading.

15. **Writes are individually atomic, not a distributed transaction.**
    - What this is: README/assets, GitHub settings, and the Git commit are distinct operations.
    - Problem: an I/O, permission, or competing-push failure can leave earlier operations completed.
    - Fix: preflight target hashes, stop on errors, rerun after resolving the cause. Do not claim all-or-nothing behavior across files/services. Branch protection may require adapting the sample to pull requests.
    - If skipped: users may mistake partial success for a completed sync.

## Verification

- Baseline: 87 tests passed. Final local suite after the README direction correction: **105 tests across 26 files passed**.
- CLI TypeScript checks and distribution build passed.
- Next.js production build passed for all routes: `/`, `/templates`, `/studio`, `/how-it-works`, `/docs`.
- The actual Action commit script was run against an isolated bare Git remote. It pushed only README and generated covers while preserving an unrelated staged owner file.
- Saved-plan freshness, malformed/nested markers, manual prose preservation, linked-parent boundaries, missing media, idempotence, remote permission errors, topic preservation, and Git-applicable large/newline patches are exercised.
- The Studio ZIP was downloaded through the browser and inspected. Every referenced sample media file was included; no fabricated license or security-policy file was exported.
- Desktop and 390px mobile screenshots were inspected. The homepage has no repository tabs, branch controls, file browser, or About sidebar. Inline section navigation works.
- Real site captures and typeset playback of actual CLI stdout are checked in. Motion supplies an animated SVG cover and a static alternative.
- The bundled skill passes the skill-creator validator. Claude Code's own plugin loader was not installed, so native plugin loading was not executed locally.
- Node 18 runtime smoke testing was attempted but the package download timed out. Development verification used Node 24; CI targets Node 22/24/26 on Linux/macOS/Windows. The first remote run passed Linux/macOS on all three Node versions and the website build. Windows exposed CRLF-only assumptions in two tests; those assertions now accept native skill-file newlines and explicitly disable Git line-ending conversion for exact patch-byte checks.

Production deployment is READY for commit `7a033c4`; the public homepage was inspected after deployment. The first PoMade Action run succeeded and committed its README refresh (`210d501`). About/topics were explicitly skipped because `POMADE_TOKEN` was absent.

Verdict: the requested presentation is deployed and push maintenance is verified. Track the unpatched development-only picomatch advisory; About/topics require the owner to save the scoped repository secret.

Not checked: exhaustive semantic proof of arbitrary owner-authored claims, a full multi-user/concurrent-writer stress test, native loading in every agent host, and Node 18 execution. Historical planning files under `mds/` were reference material rather than executable product instructions.
